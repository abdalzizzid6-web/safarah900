# تقرير تبسيط وتحسين الهيكلية البرمجية

**تاريخ التقرير:** 1 أغسطس 2026  
**المشروع:** SAFARA 90 (صفارة 90)  
**حالة النظام:** مستقر ويعمل في بيئة الإنتاج على Cloud Run و Vercel.

## 1. ملخص الهيكلية العامة والتحليل الشامل (Executive Summary)

يتكون مشروع SAFARA 90 من خمس طبقات رئيسية. تم إجراء تحليل هندسي شامل للحد من التعقيد الزائد (Over-engineering)، القضاء على التكرار، وتبسيط المسارات التنفيذية بين المكونات والخادم والأنظمة الأخرى.

```
+-----------------------------------------------------------------------+
|                           CLIENT LAYER                                |
|  +--------------------------------+   +----------------------------+  |
|  |  src/ (React Web App & Admin)  |   |  mobile/ (Expo Native)     |  |
|  +---------------+----------------+   +--------------+-------------+  |
+------------------|-----------------------------------|----------------+
                   |                                   |
                   +-----------------+-----------------+
                                     | HTTP / JSON API
                                     v
+-----------------------------------------------------------------------+
|                          BACKEND LAYER                                |
|  +--------------------------------+   +----------------------------+  |
|  | api/ (Vercel Serverless Proxies)|-->| server/ (Express Server)   |  |
|  +--------------------------------+   +--------------+-------------+  |
+------------------------------------------------------|----------------+
                                                       |
                                                       v
+-----------------------------------------------------------------------+
|                          DOMAIN CORE LAYER                            |
|  +-----------------------------------------------------------------+  |
|  | core-engine/domain/ (Shared Entities: Match, News, Team, User) |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

## 2. تحليل العلاقة بين الطبقات وتحديد الأدوار (Layer Relationships)

### 1. `src/` (طبقة واجهة الويب ولوحة التحكم - Web Frontend)
- **الدور**: تطبيق React SPA/SSR تفاعلي مبني بـ Vite و Tailwind CSS ويشمل صفحات الزوار ولوحة التحكم الشاملة.
- **العلاقة مع الطبقات الأخرى**:
  - يتصل حصرياً بـ `/api/*` عبر العميل الموحد `src/core/api/apiClient.ts`.
  - يستهلك النماذج من `core-engine/domain/entities/` لتوحيد تعريفات البيانات (`Match`, `News`, `User`, `Team`).
  - **ممنوع الاستدعاء المباشر للمزودات الخارجية**: لتفادي تسريب مفاتيح API في المتصفح.
- **القرار**: **تُحفظ كطبقة العرض الرئيسية للويب (KEEP)**.

---

### 2. `server/` (طبقة الخادم المركزي - Express Full-Stack Server)
- **الدور**: بيئة التشغيل الخلفية المركزية المعتمدة على Node.js و Express.
- **الوظائف المنجزة**:
  - معالجة طلبات API وحماية المفاتيح.
  - جلب كاش المباريات والأخبار وإدارة Firestore (`server/firestore/`).
  - توليد محتوى Gemini AI وحساب التوقعات المخزنة.
  - جلب ومعالجة خلاصات RSS وتتبع المباريات المباشرة.
  - إدارة معدل الطلبات (Rate Limiting) والأمان.
- **القرار**: **تُحفظ كالمحرك الأساسي والوحيد المعتمد للبيانات والخادم (KEEP & PRIMARY)**.

---

### 3. `api/` (طبقة الدوال بدون سيرفر - Serverless Function Endpoints)
- **الدور**: غلاف خفيف (Thin Proxy Wrappers) مخصص لتوافقية النشر على Vercel Serverless Functions.
- **العلاقة مع `server/`**:
  - ملف `api/index.ts` يحول الطلبات مباشرة إلى تطبيق Express في `server/index.ts`.
  - باقي الملفات (`api/matches.ts`, `api/ai.ts`, `api/rss.ts`, `api/seo.ts`) تستدعي مباشرة الخدمات الموجودة داخل `server/services/` و `server/firestore/`.
- **القرار**: **إبقاء الأغلفة الخفيفة للـ Serverless مع تفريغ ونقل أي منطق ثقيل إلى `server/services/` لمنع التكرار (MERGE & SIMPLIFY)**.

---

### 4. `core-engine/` (طبقة القواعد والنماذج - Clean Architecture Core)
- **التقييمالهندسي**: كانت تحوي محاكاة كاملة لـ Clean Architecture مع حالات استخدام (Use Cases) ومزودات موازية غير مستخدمة فعلياً وتسبب بطئاً وتعقيداً.
- **التنظيف والتبسيط المنجز**:
  - **تم حذف 18 ملفاً ميتًا**: بما فيها Use Cases ملغاة (`GetLiveMatches`, `SyncMatches`, `RefreshCache`, إلخ) ومزودات غير مستخدمة (`FirestoreProvider`, `FootballDataProvider`, `SportMonksProvider`, `RSSProvider`).
  - **الإبقاء فقط على النماذج الحية**: `core-engine/domain/entities/` (`Match.ts`, `News.ts`, `Team.ts`, `User.ts`, `League.ts`, `Player.ts`, `Standing.ts`, `Competition.ts`, `Channel.ts`) والواجهات الحية المستوردة في `server/compositionRoot.ts`.
- **القرار**: **تجريد وتبسيط الطبقة واختصارها في النماذج الشائعة والواجهات المعتمدة فقط (SIMPLIFY & TRUNCATE)**.

---

### 5. `mobile/` (تطبيق الهاتف المحمول - Expo / React Native App)
- **الدور**: تطبيق هواتف أصلية مستقيل يعتمد على Expo و React Native.
- **العلاقة مع الطبقات الأخرى**: يستهلك نفس واجهات API الخادمة `/api/*` دون الاعتماد على مكتبات الويب.
- **القرار**: **تُفصل وتُعزل تماماً لمنع تسرب حزم React Native إلى بناء الويب في Vite (KEEP SEPARATED)**.

---

## 3. القرارات الهندسية الأربعة (The 4 Architectural Actions)

| الفئة | الطبقة / المكون | الإجراء المتخذ والسبب |
| :--- | :--- | :--- |
| **ما يجب أن يبقى (KEEP)** | `src/` & `server/` | المحافظة على واجهات الويب وخادم Express كأعمدة أساسية للنظام. |
| **ما يجب أن يبقى (KEEP)** | `mobile/` | الإبقاء عليه كتطبيق مستقل معزول عن حزمة الويب. |
| **ما يجب أن يبقى (KEEP)** | `core-engine/domain/entities/` | النماذج والهياكل البرمجية الموحدة المستخدمة في التطبيق والخادم. |
| **ما يجب دمجه (MERGE)** | منطق `api/` مع `server/services/` | تحويل `api/` إلى أغلفة استدعاء خفيفة تعتمد كلياً على خدمات `server/`. |
| **ما تم حذفه ونقله (REMOVE & CLEANUP)** | أكواد `core-engine` الميتة | **تم حذف 18 ملفاً ميتًا** تشمل Use Cases ومزودات واختبارات قديمة ملغاة. |
| **ما يجب فصله (SEPARATE)** | حزم Native وحزم Web | منع استيراد أي ملف من `mobile/` داخل `src/` لضمان خفة سرعة التحميل. |

## 4. النتائج النهائية والأرقام القياسية

1. **تقليل التعقيد البرمجي**: إزالة مسارات المعالجة المزدوجة وتبسيط وصول البيانات.
2. **سرعة البناء والتطوير**: تسريع فحص الأنواع (TypeScript Check) وضمان عدم وجود دوال ضائعة.
3. **وضوح مصدر الحقيقة (Single Source of Truth)**:
   - البيانات والخدمات: `server/services/` و `server/firestore/`.
   - النماذج الهيكلية: `core-engine/domain/entities/`.
   - العرض والواجهة: `src/`.
